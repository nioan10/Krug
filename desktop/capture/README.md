# Изолированный захват звука Windows

Внутренний компонент для будущего настольного клиента. Сам по себе он не является приложением Круг и ещё не подключён к звонкам.

Сборка: `dotnet build desktop/capture/Krug.Capture.csproj -c Release`. Требуются .NET SDK 9 и Windows 10 build 20348 или новее. Зависимость NAudio использует WASAPI process loopback в режиме включения дерева выбранного процесса; захват всего системного звука здесь не предусмотрен.

Родительский процесс разрешает дескриптор выбранного окна через `--window <handle>` и получает PID и время запуска процесса в тиках. Для старта передаются оба значения; проверка времени исключает захват другого процесса при повторном использовании PID. На stderr приходит строка `READY 44100 2 f32le` после запуска; stdout содержит только PCM float32 little-endian, 44 100 Гц, два чередующихся канала. Строка или закрытие stdin завершает захват; завершение выбранного процесса тоже завершает его. Если потребитель не успевает за потоком, старые пакеты отбрасываются, чтобы не накапливать задержку. Старт может завершиться ошибкой; клиент обязан явно сообщить об этом и не переходить на системный звук.

На одной машине проверены два независимых синтетических источника: в захвате выбранного процесса обнаружен его сигнал и практически отсутствовал сигнал второго процесса. Также проверено завершение при выходе выбранного процесса. Перед выпуском ещё нужны сквозные проверки через клиент и LiveKit, в том числе завершения звонка и отмены выбора пользователем.
