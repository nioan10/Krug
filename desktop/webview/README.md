# Изолированный прототип WebView2

Это исследовательский прототип, не замена установленного клиента. Он открывает только тестовый локальный адрес `http://127.0.0.1:9350`, не подключается к действующему серверу и отклоняет запросы доступа к устройствам. `bridge.js` подключён только к главному окну этого тестового адреса: пока доступны лишь обмен тестовым состоянием звонка и заглушка состояния обновлений. Захват и настоящие обновления не реализованы.

Для будущего установщика добавлен и отдельно проверяется механизм ожидания окончания звонка; загрузка и установка обновлений ещё не подключены. Изолированную проверку моста можно запустить после сборки командой `node scripts/test-webview-prototype.mjs`, а проверку логики обновлений — `dotnet run --project tests/webview-update-gate`.

Для сборки нужны .NET SDK, .NET Framework 4.8 и доступ к NuGet: `dotnet build desktop/webview/Krug.Webview.csproj -c Release`. На Windows 11 системный WebView2 Runtime обычно уже установлен; на некоторых Windows 10 его понадобится установить отдельно. Прототип на этой машине загрузил тестовый интерфейс в системном WebView2; в отдельном тесте проверена передача синтетических PCM-данных в JavaScript без воспроизведения.

Отдельная оболочка собирается проектом `desktop/webview/desktop/Krug.Desktop.csproj`; обычная сборка запускается только с аргументом `--experimental`. Команда `pnpm desktop:build:webview-preview` готовит изолированный пробный установщик с отдельным идентификатором приложения в `.local`. Команда `pnpm desktop:build:webview-release` создаёт локального кандидата с рабочим идентификатором и проверкой WebView2 до изменения установки. Обе сборки используют неурезанный звуковой модуль и требуют NSIS.

Для новой оболочки реализованы отдельный выбор приложения для звука, запуск WASAPI-модуля, перенос сессии и автообновление с проверкой SHA-512. На изолированной установке проверен переход с Electron и запуск WebView2; синтетические звук и видео переданы второму участнику локального LiveKit. Реальные микрофон, экран и сторонние приложения в этих проверках не использовались.

Для поэтапной миграции сервер выдаёт старым клиентам `legacy.yml`; промежуточный Electron обязан поддерживать `migration-v1`. Версия переходного клиента должна быть ниже версии WebView2 (например, Electron 0.1.2 → WebView2 0.2.0), а основной `latest.yml` для WebView2 должен содержать `krugRuntime: webview2`. До выпуска лёгкой версии необходимо подготовить и проверить оба канала, включая давно не запускавшиеся установки. Механизмы переноса входа, проверки хеша и ожидания конца звонка имеют изолированные тесты, но реальный переход установщика ещё не проверен.

Отдельно `pnpm desktop:prepare:experimental-trim` собирает в `.local/capture-experimental-trim` экспериментальный звуковой модуль с урезанной средой .NET. Библиотеки NAudio сохраняются целиком. Обычная команда сборки приложения его не использует: прежде чем включать его в релиз, необходимо проверить реальную передачу и изоляцию звука, завершение процесса и обновление установленного клиента. Экспериментальную папку нельзя публиковать как релиз.
