# Круг

Голосовые комнаты, чат и демонстрация экрана для небольшой компании. Работает в браузере и устанавливается как PWA. Сервер приложения, база и LiveKit размещаются у вас.

**Статус: первая версия (0.1.0).** Локально проверены API, доставка сообщений и передача синтетического аудио/видео между двумя WebRTC-клиентами. Публичное развёртывание, TURN/TLS и звонки из разных сетей нужно проверить на вашем VPS перед постоянным использованием.

## Возможности

- Голосовые комнаты, камера, демонстрация экрана и звук демонстрации, если браузер его поддерживает.
- Микрофон и камера выключены при входе. Выбор микрофона и камеры; отдельное отключение входящего звука.
- Переключение между текстовыми каналами без выхода из звонка.
- Чат с историей, загрузкой старых сообщений и переподключением.
- **История хранится бессрочно. Автоматического удаления нет.** Участник удаляет свои сообщения, владелец — любые сообщения или историю канала с подтверждением.
- Регистрация по одноразовым приглашениям, владелец создаёт каналы и приглашения.
- Установка на компьютер или телефон, отдельное окно и иконка приложения.
- Интерфейс на русском, адаптация к небольшим экранам.

В первой версии нет личных сообщений, файловых вложений, ботов, сложных ролей, восстановления пароля по email и сквозного шифрования. Все зарегистрированные участники видят все каналы.

## Установить приложение

Откройте работающий сервер и нажмите **«Установить приложение»**.

- На компьютере используйте Chrome или Edge: установка также есть в адресной строке или меню браузера.
- Android: Chrome → меню → «Установить приложение».
- iPhone/iPad: Safari → «Поделиться» → «На экран Домой».
- macOS: Safari → «Файл» → «Добавить в Dock» или установка через Chrome.

Если сайт открыт во встроенном браузере другого приложения, откройте его адрес в обычном браузере. Нужен HTTPS; `localhost` разрешён для локальной проверки. Это PWA. Отдельный Windows-клиент с захватом звука выбранного процесса находится на этапе проверки; сведения о сборке и обновлениях — в [desktop/README.md](desktop/README.md). Отдельного APK пока нет. Возможность захвата экрана и системного звука в браузере зависит от браузера и ОС; для демонстрации используйте настольный Chrome/Edge. На телефонах ОС может приостанавливать звонок в фоне.

PWA кеширует только интерфейс. Сообщения, сессии и медиатокены не сохраняются в Cache Storage. Без связи с сервером переписка и звонки недоступны. Открытое приложение проверяет обновления раз в минуту, при возврате в окно и восстановлении связи. Во время звонка кнопка «Обновить после звонка» ставит установку в очередь: она начнётся после выхода из комнаты. Очередь можно отменить. Вне звонка кнопка «Обновить» устанавливает новую версию сразу.

## Локальный запуск

Нужны **Node.js 24+** и **pnpm 11.25.0**. Пример установки менеджера пакетов: `npm install --global pnpm@11.25.0`.

```sh
git clone https://github.com/nioan10/Krug.git
cd Krug
pnpm install --frozen-lockfile
node scripts/setup.mjs
pnpm dev
```

Откройте `http://localhost:5173`. Одноразовая ссылка регистрации владельца находится в `.setup/first-invite.txt`. Сначала зарегистрируйте владельца, затем создавайте приглашения для друзей. Пароль — минимум 12 символов. Приглашение владельца действительно 7 дней с первого запуска сервера.

**Без LiveKit чат работает, звонки — нет.** Загрузите [LiveKit Server v1.13.11](https://github.com/livekit/livekit/releases/tag/v1.13.11), проверьте SHA-256 по `checksums.txt` из того же релиза и распакуйте бинарный файл:

- Windows: `.local/bin/livekit-server.exe`;
- Linux: `.local/bin/livekit-server` (потребуется `chmod +x`).

`pnpm dev` автоматически запустит найденный бинарный файл. Можно запустить его вручную с параметрами `--config deploy/livekit.yaml`. macOS: установите LiveKit отдельно по официальной инструкции и передайте ту же конфигурацию.

Локальная конфигурация предназначена **для одного компьютера**. Она привязана к localhost и не предназначена для доступа друзей через интернет или локальную сеть. Windows-версия LiveKit сообщает, что мониторинг CPU не поддерживается; Linux VPS нужен для постоянного сервера.

Для проверки именно собранной PWA:

```sh
pnpm build
```

Остановите `pnpm dev`, измените `APP_ORIGIN` в локальном `.env` на `http://localhost:3000`, затем выполните `pnpm start` и откройте этот адрес. Для звонков запустите LiveKit отдельно. Возвращаясь к `pnpm dev`, верните `APP_ORIGIN=http://localhost:5173`.

## Установка на VPS

Нужен Linux VPS с публичным IPv4, Docker Engine + Compose и три DNS-имени. Для начала можно выделить 2–4 vCPU и 4 GB RAM; это ориентир для испытаний, а не гарантия вместимости. Видеодемонстрации сильнее всего зависят от исходящей полосы сервера. Для 5–15 человек проверьте ваш обычный сценарий под нагрузкой.

1. Создайте DNS A-записи `chat.example.com`, `rtc.example.com`, `turn.example.com` на IPv4 сервера. Используйте прямые DNS-записи без HTTP/CDN-проксирования. Не создавайте AAAA, если IPv6 не настроен.
2. Откройте необходимые порты в firewall ОС и панели хостинга (таблица ниже). Сохраните доступ по SSH.
3. В **свежем клоне на VPS** с Node.js 24 запустите:

```sh
node scripts/setup.mjs --domain chat.example.com --media-domain rtc.example.com --turn-domain turn.example.com --public-ip 203.0.113.10
docker compose config --quiet
docker compose run --rm --no-deps caddy validate --config /etc/caddy.json
docker compose up -d --build
docker compose ps
```

Замените примеры своими доменами и **реальным публичным IPv4**. Адрес `203.0.113.10` приведён только как пример. Ключи генерируются случайно. Скрипт отказывается перезаписывать существующий `.env`.

| Порт | Назначение | Доступ извне |
| --- | --- | --- |
| TCP 80 | Выпуск/продление сертификатов, HTTP → HTTPS | Да |
| TCP 443 | Сайт, сигнализация WebRTC, TURN/TLS | Да |
| TCP 7881 | Резервный прямой WebRTC по TCP | Да |
| UDP 7882 | Основной медиатрафик WebRTC | Да |
| UDP 3478 | TURN/UDP | Да |
| UDP 30000–30100 | Диапазон TURN relay | Да |
| TCP 3000, 7880 | Приложение и LiveKit API | Нет, localhost |
| TCP 5349 | Внутренний вход TURN после TLS-прокси | Нет, закрыть firewall |

Caddy выпускает сертификаты и обслуживает сайт. Его Layer 4 wrapper перенаправляет TURN-домен на встроенный TURN LiveKit, остальные HTTPS-запросы обрабатываются обычным HTTP reverse proxy. PROXY protocol v2 передаёт TURN реальный адрес клиента. Доступ к внутреннему TURN разрешён только с доверенного localhost-прокси. Приложение доверяет forwarded-заголовкам только от localhost; не выставляйте его порт напрямую наружу.

Compose использует `network_mode: host` и рассчитан на **Linux**, не на Docker Desktop в Windows/macOS. SQLite хранится в томе `krug_data`, сертификаты — в `caddy_data`. Для одного узла Redis не требуется. Масштабирование в несколько экземпляров приложения не поддерживается: presence и рассылка сообщений находятся в памяти процесса.

После запуска откройте ссылку из `.setup/first-invite.txt`, зарегистрируйте владельца и пригласите друзей. Готовый сервер должен быть доступен по `https://chat.example.com`.

## Проверки

```sh
pnpm test
pnpm build
node --env-file=.env scripts/test-media.mjs
```

Последняя команда требует запущенный LiveKit и создаёт временную комнату с двумя клиентами. Она передаёт искусственные аудио/видеокадры, не обращается к микрофону или экрану и удаляет свою тестовую комнату. Не запускайте на чужом сервере.

GitHub Actions выполняет тесты, сборку, Docker build и проверку сгенерированной серверной конфигурации. Перед использованием VPS проверьте вход двух человек из разных сетей, голос, экран, смену комнаты, восстановление после потери сети и соединение с запрещённым UDP через TURN/TLS. Зелёный CI не подтверждает прохождение блокировок провайдера.

## Данные и резервные копии

**Не выполняйте `docker compose down -v`: эта команда удаляет тома и историю.** Обычный `docker compose down` сохраняет данные.

Остановите приложение на время копирования SQLite, чтобы получить согласованную базу вместе с WAL. Пример для Linux, из каталога проекта:

```sh
mkdir -p backups
docker compose stop app
docker compose cp app:/app/data/. ./backups/
docker compose start app
```

Сохраните отдельную защищённую копию `.env`, `deploy/livekit.yaml`, `deploy/caddy.json`. В резервных копиях содержатся переписка, хеши паролей и сессий; храните их как приватные данные, желательно в зашифрованном виде. Копии не удаляются при очистке истории через интерфейс. Каталог `backups/` исключён из Git.

При восстановлении сначала остановите приложение, верните всю сохранённую папку данных в том, сохранив владельца UID/GID `1000:1000`, затем запустите приложение. Перед заменой сохраните текущую базу отдельно. При миграции меняется адрес сайта — обновите конфигурацию и переустановите PWA для нового адреса.

## Безопасность и ограничения

См. [SECURITY.md](SECURITY.md). HTTPS/WSS и WebRTC шифруют соединения, но **сквозного шифрования нет**. Владельцу сервера доступны сообщения и медиатрафик; история на диске не зашифрована самим приложением. Запись звонков не реализована.

Свой домен и TURN/TLS дают дополнительные варианты подключения. Это не обещание обхода любой блокировки: IP, домен, TLS и сам WebRTC тоже могут блокироваться. Если ваши сети блокируют все доступные пути, потребуется менять размещение или транспорт.

## Структура

```text
src/          React-интерфейс, LiveKit, установка PWA
server/       Fastify API, SQLite, сессии, приглашения, WebSocket
scripts/      Настройка, сборка service worker, медиатест
tests/        Проверки доступа, истории, сессий, PWA
public/       Manifest и иконки
compose.yaml  Приложение, LiveKit и Caddy
```

Зависимости зафиксированы в `pnpm-lock.yaml`. `.env`, базы, приватные конфигурации, тестовые артефакты и файлы агентов исключены из Git. Перед публикацией полезно проверить `git status --short` и `git diff --cached --stat`.
