# Публичные эфиры

Автор входит в Округ для Windows, открывает «Транслировать», выбирает окно и звук приложения, проверяет предпросмотр и нажимает «Начать эфир». В блоке «Ссылка на эфир» есть копирование адреса. Открывать эфир зрители могут в обычном браузере, в том числе на телефоне, без аккаунта. Общего каталога нет; каждый запуск получает новую случайную ссылку. Любой получатель может переслать её дальше.

В чате у всех случайные ID, включая автора и пользователей Округа. ID сохраняется в этом браузере для конкретного эфира, между эфирами меняется. Имя аккаунта, аватар и IP не отображаются. Это анонимность перед участниками: сервер видит сетевые адреса и владельца эфира. Автор может удалять сообщения и запрещать гостю писать; запрет привязан к гостевой сессии и обходится новым браузером. Дополнительно действуют ограничения частоты по IP и гостю.

Видео и звук передаются через отдельный LiveKit, публичный API работает отдельным процессом и не получает базу аккаунтов, приватные сообщения или ключи приватного LiveKit. Соединения защищены HTTPS/WSS и DTLS-SRTP; сквозного шифрования нет. Запись/VOD не реализованы. История чата сохраняется без автоматического срока удаления в отдельном томе `stream_data`.

## Захват и качество

- Публикация: текущий Windows-клиент с нативным захватом звука; веб-клиент предлагает скачать его. Новая версия exe для этой функции не нужна.
- Выбирается отдельное окно. Захват рабочего стола или вкладки отклоняется. Системный звук через браузер не запрашивается, микрофон не захватывается.
- Звук берётся из выбранного процесса и его дочерних процессов. В окне выбора звука нужно выбрать то же приложение, что для картинки. Если у приложения несколько окон в одном процессе, их звук может быть общим. Защищённые DRM-источники и некоторые игры могут не поддерживать захват.
- При отмене выбора звука системный звук не подставляется: можно повторить выбор либо включить «Без звука».
- Одновременно доступен один нативный захват: публичный эфир или демонстрация в комнате. Разговор в Округе можно продолжать во время эфира.
- 720p60: до 4 Мбит/с видео + 128 Кбит/с стерео. 1080p60: до 8 Мбит/с + звук. Фактическая частота и качество зависят от окна, компьютера и сети. Автоматического переключения разрешений нет.
- До двух активных эфиров, по одному на аккаунт; до 15 подключений зрителей на эфир. Плановая нагрузка первой версии — до 15 зрителей суммарно. Вкладки считаются отдельно.
- Закрытие окна захвата завершает эфир. Если приложение исчезнет без уведомления сервера, эфир закроется после истечения аренды (обычно до 65 секунд). История и старая ссылка остаются доступны, видео останавливается.

При 15 зрителях суммарно верхняя оценка исходящего трафика — около 28 ГБ/час в 720p60 или 55 ГБ/час в 1080p60, плюс служебный трафик и остальные сервисы. Это расчёт по пределу битрейта, не гарантия месячного потребления.

## Установка на существующий Linux VPS

Сначала сделайте резервную копию `.env`, конфигурации и базы. Создайте три A-записи на IPv4 сервера: `stream`, `stream-rtc`, `stream-turn`. Затем из каталога проекта:

```sh
node scripts/setup-streams.mjs \
  --domain stream.example.com \
  --media-domain stream-rtc.example.com \
  --turn-domain stream-turn.example.com \
  --public-ip 203.0.113.10
```

Замените все примеры своими значениями. Скрипт генерирует отдельные ключи, дополняет `.env` и Caddy, сохраняет предыдущие файлы в `.setup/before-streams-*` и отказывается повторно перезаписывать настройки эфиров. Секреты и созданная конфигурация исключены из Git и Docker build context.

Откройте дополнительные порты:

| Порт | Назначение |
| --- | --- |
| TCP 7891 | WebRTC TCP |
| UDP 7892 | WebRTC UDP |
| UDP 3479 | TURN UDP |
| UDP 30110–30210 | TURN relay |
| TCP 3001, 7890, 5350 | Только внутренние; извне закрыты |

Сайт и TURN/TLS используют уже открытые 80/443. На работающем сервере:

```sh
docker compose build app
docker compose --profile streams up -d --no-deps --no-build --wait app streams stream-livekit
docker compose exec caddy caddy validate --config /etc/caddy.json
docker compose kill -s USR1 caddy
```

SIGUSR1 перечитывает конфигурацию Caddy 2.11+, запущенного с `run --config`, без остановки существующих соединений. На новом сервере можно запустить весь набор через `docker compose --profile streams up -d --build`. Приватный LiveKit не требует перезапуска. Проверьте HTTPS на всех трёх доменах, `/api/health` публичного сервиса, реальную передачу видео/звука и TURN/TLS из внешней сети.

## Резервное копирование и восстановление

В копию должны входить `.env`, `compose.yaml`, `deploy/livekit.yaml`, `deploy/stream-livekit.yaml`, `deploy/caddy.json`, обе SQLite-базы и сертификаты. Для онлайн-копии используйте SQLite `.backup`; простое копирование открытого файла без WAL может потерять сообщения. База эфиров находится в `stream_data:/app/streams/streams.sqlite`. При восстановлении остановите `app` и `streams`, сохраните текущие данные отдельно и восстановите файлы с владельцем `1000:1000`, затем запустите оба сервиса. Не используйте `docker compose down -v`.

Без `STREAM_ORIGIN` основное приложение работает как раньше и скрывает кнопку эфиров. Для отключения эфиров сначала завершите их, остановите `streams` и `stream-livekit`, очистите переменные `STREAM_*` в `.env` и пересоздайте только `app`. Том истории можно оставить для последующего восстановления.
